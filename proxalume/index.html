01 / Project overview

Software is more than a collection of files.

Maintaining unfamiliar applications, reviewing legacy systems or investigating a compiled program often means piecing together information from many different tools. Proxalume brings those perspectives into one desktop environment so an engineer can follow a relationship from a source symbol to a dependency, a request path, a finding or a binary function.

The project combines a C#/.NET 10 analysis engine and Avalonia desktop interface with a separate commercial web platform. Its central idea is evidence-driven understanding: make relationships visible, distinguish known facts from inferences, and keep the analyst in control of the conclusions.

Designed for real engineering work

  • Understand unfamiliar repositories and legacy systems.
  • Investigate dependency chains and architectural changes.
  • Inspect compiled programs without launching the target during static analysis.
  • Preserve findings and share review evidence.

02 / Workbench capabilities

One environment. Multiple ways to investigate.

Capabilities vary with language, architecture, file format and available evidence. Each view answers a different question about the system.

01 · SOURCE

Multi-language intelligence

Inspect PHP and Laravel, JavaScript and TypeScript, C#, Python, Java, C/C++, SQL and supported configuration files. Discover symbols, imports, declarations, calls and dependency relationships. The C# analyzer uses Roslyn; analysis depth differs across languages.

02 · GRAPH

2D relationship explorer

Navigate a directed graph of files, classes and functions. Follow callers and dependencies, isolate nearby components, investigate cycles and trace paths. Distinct relationship evidence helps separate resolved references from inferred links.

03 · VISUALIZATION

3D Code City

Explore a codebase as an architectural landscape. Buildings encode measures such as lines of code and complexity, making dense areas and large components easier to identify. The visualization is a starting point for investigation, not a quality score.

04 · WEB SYSTEMS

Laravel and database flow

Follow statically discovered routes, middleware, controllers, services, Eloquent relationships, migrations and Blade templates. Connect recognized frontend API requests to backend routes and inspect schema relationships across the application.

05 · CHANGE

Impact and snapshot comparison

Compare saved analyses and local Git revisions. Identify added, removed and changed components, inspect complexity and line-count changes, and trace potentially affected callers and dependencies. Track new, resolved and persistent findings over time.

06 · QUALITY

Security and project health

Investigate potential injection, unsafe execution, hardcoded secrets, risky deserialization and other supported rules. Review source locations and analysis coverage, including skipped or unsupported input. Findings are leads, not definitive vulnerability judgments.

07 · BINARY

Binary Workbench

Inspect PE, ELF, Mach-O and correctly configured raw or firmware images. Explore hashes, strings, imports, functions, cross-references, instructions and control-flow graphs. Record annotations and review native pseudo-C recovery alongside disassembly.

x86/x64 and ARM families have deeper documented coverage; MIPS, PowerPC and RISC-V results require particular care. Managed .NET assemblies receive metadata summaries rather than full reconstructed C#.

08 · SUPPLY CHAIN

Dependencies and provenance

Inventory supported npm, Composer and NuGet manifests and lockfiles. Produce CycloneDX software bills of materials, examine cached or imported advisory information, request online advisory lookups when appropriate, and compare hashes and supported provenance attestations.

09 · FORENSICS

Digital forensic evidence

Investigate supported Windows minidumps, shortcut and Prefetch artifacts, and read-only browser SQLite histories. Evaluate YARA and Sigma rules, compare API contracts and export evidence into tamper-evident case containers with integrity records.

Evidence, not certainty. Static analysis cannot observe every runtime path, reflection target or dynamically constructed relationship. Pseudo-C is approximate, and a matching hash or an empty findings list does not establish that software is safe. Execution and debugging are separate actions requiring an appropriate isolated environment.

03 / Practical workflows

From questions to evidence.

01

Open

Choose a local project, supported binary or forensic artifact. For a remote repository, use the configured Git client.

02

Analyze

Build the relationship graph or inspect file structure. Review what was analyzed, what was inferred and what could not be understood.

03

Investigate

Trace dependencies, compare snapshots, inspect a function or evaluate a finding against its underlying evidence.

04

Document

Export structured results, record annotations or preserve a case for follow-up review and collaboration.

Example: onboarding to a Laravel application

A developer can begin with a repository graph, inspect the routes and controller relationships, follow models to their migrations, and compare the result with a baseline before changing a shared service. This makes the review more focused than reading files in isolation.

Example: reviewing an unfamiliar executable

An analyst can examine file metadata, imported functions, strings and cross-references without starting the program. Function graphs and approximate pseudo-C help prioritize further investigation; notes and exports preserve the rationale for later review.

Interoperable outputs

Use JSON and CSV for structured data, SARIF for static-analysis findings, DOT and GraphML for graph interchange, CycloneDX for component inventories, and supported forensic case bundles for evidence workflows. Export coverage depends on the analysis type. The built-in offline guide provides documentation without a network connection.

05 / Engineering philosophy

Local-first, evidence-led, release-controlled.

Privacy and user control

Core static analysis is designed to run locally without background telemetry. Repository cloning, update checks, online advisory queries and explicitly configured integrations may require network access. A local workflow does not mean every optional feature is offline.

License activation requires a connection; valid activated licenses support offline use. Current plan and release terms are available from the product website.

Controlled release engineering

Builds target Windows and Linux, with signed update manifests, integrity inventories, differential patches, checksums and a software bill of materials. Releases are evaluated through code review, regression tests, package verification and installation checks before distribution.

Update signing is distinct from operating-system code-signing certificates. Signatures prove the integrity and origin of the signed data within their trust model, not that a program is free of defects.

07 / Frequently asked questions

What to know before exploring Proxalume.

Is Proxalume the same as WebToApp Studio Pro?

No. Both are WildCat Studio projects. WebToApp packages existing web applications into desktop or mobile projects; Proxalume is a software-analysis and investigation workbench.

Does Proxalume upload my source code?

Core static analysis is local-first. Optional network features such as cloning, update checks and explicitly requested advisory lookups have separate network requirements. Review the product documentation before using external integrations with sensitive projects.

Can it reconstruct the original source of an executable?

Native pseudo-C helps interpret machine code, but cannot recover original source, comments, names or types reliably in every case. It should be checked against the underlying instructions. Managed .NET metadata inspection is not full C# decompilation.

Does it replace a debugger, security audit or forensic investigation?

No. It provides evidence and navigation tools that complement specialist workflows. Unsupported constructs, incomplete evidence and runtime behavior require independent investigation.

Can I use it offline?

Core local analysis and the bundled guide work offline. Initial online license activation and optional network operations require connectivity. Offline use remains subject to the applicable license and trial terms.

Where can I obtain the latest release or commercial terms?

Visit the official Proxalume website for current availability, published downloads, pricing and support. This studio showcase is not a download mirror and does not imply that a candidate has been released.
